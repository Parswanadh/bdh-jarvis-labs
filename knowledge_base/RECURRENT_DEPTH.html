BDH Master Class: Recurrent Depth - Looped Inference & ACT

1. Concept of Recurrent Depth

Traditional deep learning architectures (like standard Transformers) utilize Spatial Depth. In these models, depth is defined by the number of unique layers $\mathcal{L}$. Information flows linearly from layer $l$ to $l+1$, where each layer possesses its own distinct set of weights $W_l$.

The Paradigm Shift: Recurrent Depth transforms the network from a sequence of unique filters into a dynamical system. Instead of increasing the number of layers to increase capacity, we apply the same transformation repeatedly to the hidden state.

Recurrent depth treats the model as a function that iterates until a certain state of refinement is reached. This is akin to how humans solve a complex problem: we do not apply a fixed number of "thought layers," but rather iterate on a mental representation until the answer becomes clear.

2. The Mythos A-Matrix

Central to advanced recurrent systems is the Learnable Decay Matrix, often referred to as the A-Matrix. Rather than simple additive residuals, the A-Matrix governs the temporal evolution of the state.

$$\mathbf{h}_{t+1} = A \mathbf{h}_t + f(\mathbf{h}_t, W)$$

The A-Matrix functions as a dynamic state-transition matrix. It determines which components of the hidden state are preserved (eigenvalues $\approx 1$) and which are forgotten (eigenvalues $\approx 0$) across iterations. By making $A$ learnable, the model can optimize its own memory decay rate, effectively learning the "time constant" of its internal reasoning process.

Dynamic Gating: In high-end implementations, $A$ is not a static matrix but a function of the input $A(\mathbf{x})$, allowing the model to adjust its internal persistence based on the complexity of the prompt.

3. Looped Inference

Looped inference is the mathematical implementation of recurrent depth. In a looped system, we share weights across the temporal dimension of the "thinking" process.

The Mathematical Framework

In a standard feedforward network: $$\mathbf{h}_{l+1} = \sigma(W_l \mathbf{h}_l + \mathbf{b}_l)$$

In a looped inference system (like a Universal Transformer), the weights are tied: $$\mathbf{h}_{t+1} = \sigma(W \mathbf{h}_t + \mathbf{b}, \mathbf{x})$$

$$\mathbf{h}_{T} = f^{(T)}(\mathbf{h}_0, W)$$ where $f^{(T)}$ denotes the function $f$ composed with itself $T$ times.

This approach drastically reduces the parameter count while potentially increasing the expressive power of the network, as the model can theoretically simulate a network of arbitrary depth $T$ using only the weights of a single layer.

4. Adaptive Computation Time (ACT)

A critical flaw in fixed-loop inference is the "one size fits all" problem: some tokens (e.g., "the") require minimal processing, while others (e.g., "quantum") require deep reasoning. ACT allows the model to decide when to stop.

The Halting Architecture

The halting probability $h_t$ is not a simple linear projection, but the output of a specialized MLP designed to analyze the state's stability. The architecture typically follows:

$$\mathbf{h}_t \rightarrow \text{Linear} \rightarrow \text{ReLU} \rightarrow \text{Linear} \rightarrow \text{Sigmoid} \rightarrow h_t$$

This non-linearity allows the model to identify complex patterns in the hidden state that signal "convergence" or "completion" of the thought process.

ACT Reality Check: Batch-Wide Averaging

While the theoretical framework suggests a per-token sum $\sum h_t \ge 1$, this leads to massive instability and "jitter" in GPU utilization during training. In robust production implementations, a Batch-Wide Average Halting mechanism is used.

The Mechanism: Instead of stopping individual tokens, the system calculates the average halting probability across the entire sequence batch. The loop terminates when the mean confidence across the batch reaches the threshold. This ensures synchronized tensor operations and stabilizes the gradient flow during backpropagation through time (BPTT).

The Pondering Mechanism

To ensure the model doesn't just stop immediately to minimize loss, a ponder cost is added to the objective function, penalizing the model for each additional step of computation:

$$\mathcal{L}_{total} = \mathcal{L}_{task} + \lambda \sum_{t=1}^{N} p_t$$ where $p_t$ is the probability that the model is still pondering at step $t$.

5. Fixed-Point Theory

Recurrent depth is fundamentally an attempt to find a Fixed Point of the transformation $f$. In the limit of infinite depth, the model seeks a state $\mathbf{h}^*$ such that:

$$\mathbf{h}^* = f(\mathbf{h}^*, W)$$

Fixed-Point Convergence occurs when the updates to the hidden state $\Delta \mathbf{h} = \| \mathbf{h}_{t+1} - \mathbf{h}_t \|$ fall below a small epsilon $\epsilon$. In the context of reasoning, this convergence represents the model reaching a logical conclusion where further "thinking" no longer changes the answer.

This relates directly to Deep Equilibrium Models (DEQ), which skip the iterations entirely and use root-finding algorithms (like Broyden's method) to jump directly to the fixed point $\mathbf{h}^*$.

6. Test-Time Compute

The "o1 paradigm" highlights a fundamental discovery: reasoning quality scales with the amount of compute spent at inference time, not just during training.

The Inference Scaling Law: If a model is trained with recurrent depth or CoT (Chain of Thought), increasing the loop depth $T$ at test time (without changing weights) can lead to a monotonic increase in performance on complex logic tasks.

Latent Loops vs. Discrete Loops

It is critical to distinguish between internal recurrent depth and external chain-of-thought:

Latent Loops (Internal): Iterations happen within the hidden state vectors.
  • Pros: Extremely fast, high bandwidth, no token cost, dense information flow.
  • Cons: Opaque (black box), harder to debug, susceptible to vanishing gradients.
Token Loops (Discrete/CoT): Iterations are written as text tokens.
  • Pros: Fully interpretable, leverages the KV cache for "working memory," easy to prompt-engineer.
  • Cons: Slow (auto-regressive), consumes context window, sparse (limited by vocabulary).

7. Training Stability

Training recurrent loops is notoriously difficult due to the Vanishing and Exploding Gradient problems. Because the same matrix $W$ is multiplied repeatedly, the gradients $\frac{\partial \mathbf{h}_T}{\partial \mathbf{h}_0}$ involve $W^T$.

Regularization Strategies

  1. Weight Tying & Normalization: Use LayerNorm or RMSNorm at every iteration to keep the hidden state magnitude stable.
  2. Residual Connections: Instead of $\mathbf{h}_{t+1} = f(\mathbf{h}_t)$, use $\mathbf{h}_{t+1} = \mathbf{h}_t + f(\mathbf{h}_t)$. This ensures that the identity mapping is the default, preventing signal decay.
  3. Gradient Clipping: Hard-limiting the norm of the gradient to prevent "spikes" during the backward pass through the loop.
  4. Stochastic Depth: Randomly skipping iterations during training to force the model to be robust to varying loop depths.
